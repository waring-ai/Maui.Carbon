Carbon is IBM's open source design system for products and digital experiences. This system carries its v11 design language: four themes, the IBM Plex type scale, the 8px mini-unit spacing and size scales, the layering model, 92 hand-built components plus an `Icon` component with 78 glyphs, and 11 pattern cards that compose them into full surfaces. Use the tokens as CSS custom properties (`var(--layer-01)`, `var(--text-primary)`, `var(--spacing-05)`, `var(--duration-fast-02)`) and the type styles as classes (`.body-compact-01`, `.heading-03`); never paste hex values. The sections after this one cover choosing between similar components and the patterns.

## Content fundamentals

Carbon is a productive, enterprise design language: the interface is the tool, so copy is plain, specific and short.

- Write in sentence case everywhere: buttons, labels, tabs, tags, headings ("Save changes", "Project name", "Quota nearly reached"). Reserve Title Case for proper nouns.
- Buttons start with a verb and name the outcome ("Add node", "Download report"). One or two words where possible; never "Click here" or "Submit" alone.
- Address the person as "you"; refer to the product by name or not at all. Avoid "we" except for the product's own voice in errors it caused.
- Notifications use a two-part pattern: a title that states the outcome ("Upload failed") and a subtitle with the reason and what to do next ("The file is larger than 50 MB. Choose a smaller file.").
- Helper text explains the format or consequence; error text says what is wrong and how to fix it. Never blame the person.
- No emoji, no exclamation marks, no marketing adjectives in product UI. Numbers are digits ("3 nodes"). Use "Cancel" for dismissing, "Close" for closing a surface.
- Form labels are one to three words, sentence case, with no trailing colon ("Cluster name", not "Name of the cluster:"). Mark whichever is the minority: if most fields are required, add "(optional)" to the optional ones; if most are optional, add "(required)". Be consistent across the product.
- Placeholder text is only a hint or example ("e.g. prod-eu-01"), never the only label or essential information; it disappears on input and is low contrast.
- Errors appear when a field loses focus and name the fix ("Use 3 to 63 lowercase letters, numbers or hyphens"). After a failed submit, summarize in an `InlineNotification` at the top and keep the field errors; clear each error as soon as it is fixed.
- Truncate with an ellipsis only where the full text stays reachable (a tooltip, a details view); never truncate button labels: let them wrap.

## Visual foundations

**Themes.** Four themes ship, all with the same token names: `white` (default), `g10` (Gray 10), `g90` (Gray 90), `g100` (Gray 100). Set `data-theme="white|g10|g90|g100"` on any container to switch it; themes nest. White and Gray 10 are light; Gray 90 and Gray 100 are dark. Never hard-code a color; always reference a token so the theme can change underneath.

**Layers, not shadows.** Depth is expressed by stepping the fill, not by drop shadows. `background` is the page. A container sits on it as `layer-01`; a container inside that uses `layer-02`; one more level uses `layer-03`. Each layer has matching `layer-hover-NN`, `layer-active-NN`, `layer-selected-NN`, `layer-accent-NN`, `border-subtle-NN`, `border-strong-NN` and `field-NN` tokens. Use the tokens of the layer you are on: inputs on `layer-01` use `field-02`; on `background` or `layer-02` they use `field-01`. Modals and side panels are scrimmed with `overlay`; `shadow` is the color to use for the drop shadow on floating surfaces such as menus and popovers.

**Color.** Blue is the only brand hue and means "interactive": `button-primary`, `link-primary`, `interactive`, `border-interactive`, `focus`. Everything else is gray. Support colors (`support-error`, `support-success`, `support-warning`, `support-info`, caution) mark status and are always paired with an icon and a text label. The 10 tag tints are for categorization only. Text on a surface: `text-primary` for primary content, `text-secondary` for labels and secondary copy, `text-helper` for helper text, `text-error` for errors, `text-on-color` on saturated fills, `text-inverse` on `background-inverse`. `text-placeholder` and `text-disabled` are intentionally low contrast in the source (below 4.5:1); never use them for essential information. Warning yellow (`support-warning`, 1.7:1 on white) is an icon fill only, never text.

**Type.** IBM Plex Sans for UI and copy, IBM Plex Mono for code (`code-01`, `code-02`), IBM Plex Serif for quotations (`fluid-quotation-01/02`); weights are 300 light, 400 regular, 600 semibold only. The UI default is `body-compact-01` (14px/18px, +0.16px tracking). Use the `compact` styles for single-line UI (buttons, menus, table cells) and `body-01/02` for paragraphs. Headings: `heading-compact-01/02` inside components, `heading-03` to `heading-07` for page and section headings. The fluid styles (`fluid-heading-03..06`, `fluid-paragraph-01`, `fluid-display-01..04`) are the base (small) value here; at the breakpoints below they step up (display-04 reaches 144px at `max`). Small text (`label-01`, `helper-text-01`) carries +0.32px tracking. Fonts load from Google Fonts; fall back to the stacks in `type.families`.

**Spacing and size.** The base is the 8px mini-unit: `spacing-01` 2px, `-02` 4px, `-03` 8px, `-04` 12px, `-05` 16px, `-06` 24px, `-07` 32px, `-08` 40px, `-09` 48px, `-10` 64px, `-11` 80px, `-12` 96px, `-13` 160px. Default component padding is `spacing-05` (16px). Control heights come from the size scale: `size-small` 32px, `size-medium` 40px, `size-large` 48px (the default), `size-xlarge` 64px, `size-2xlarge` 80px. Never use an off-scale value.

**Grid and breakpoints.** The 2x grid is built from the 8px mini unit. Breakpoints are tokens (`breakpoint-sm` 320px with 4 columns and no margin, `breakpoint-md` 672px with 8 columns, `breakpoint-lg` 1056px and `breakpoint-xlg` 1312px with 16 columns and 16px margins, `breakpoint-max` 1584px with 16 columns and 24px margins); use them as `@media (min-width: …)` values. Every column has 16px padding, so gutters are 32px; type aligns to the padding edge, never sits in it. Use a gutterless (condensed) grid only for closely related content such as a tile gallery. Fixed boxes and vertical margins come from the sizing scale (8, 16, 24, 32, 48, 64, 80px) and the aspect ratios 1:1, 2:1, 2:3, 3:2, 4:3 and 16:9 (`AspectRatio`). Lay pages out with `Grid`/`Column`, and stack content inside a column with `Stack` and the spacing tokens. Between fluid sections of expressive pages use `fluid-spacing-01..04` (0, 2vw, 5vw, 10vw), never inside components.

**Shape and borders.** The system is square: buttons, inputs, tiles, notifications and modals have no radius (`radius-none`). Round shapes are exceptions: tags are pills (`radius-tag`), toggles are pills with a circular knob (`radius-toggle`, `radius-circle`), checkboxes use a 2px corner (`radius-checkbox`). Inputs have no outline border, only a 1px `border-strong-01` bottom rule. Separate content with 1px `border-subtle-NN` hairlines.

**Focus.** Every interactive element shows a 2px solid `focus` outline (inset -2px on fields, tabs and tiles; +1px offset on checkboxes, toggles and tags; a 1px `focus` border plus inset ring and 2px `background` inner ring on filled buttons). `focus` is blue-60 (`#0f62fe`) on White and Gray 10 and white on Gray 90 and Gray 100, and holds 3:1 against its surfaces; `focus-inset` is the matching inner ring. Never remove it.

**States.** Hover steps the fill (`layer-hover-NN`, `background-hover`, `button-*-hover`); pressed steps further (`layer-active-NN`, `background-active`, `button-*-active`); selected uses `layer-selected-NN` / `background-selected`; disabled uses `button-disabled` fills with `text-on-color-disabled`, or `text-disabled` and `icon-disabled`. Skeleton placeholders use `skeleton-background` and `skeleton-element`.

**Motion.** Productive motion (subtle, efficient) is the default for task UI; expressive motion is for occasional, significant moments such as opening a new page or a primary action. Durations are tokens and scale with the size of the change: `duration-fast-01` (70ms) for button and toggle micro-interactions, `duration-fast-02` (110ms) for fades, `duration-moderate-01` (150ms) for small expansions, `duration-moderate-02` (240ms) for expansions, toasts and modals, `duration-slow-01` (400ms) for large expansions and important notifications, `duration-slow-02` (700ms) for background dimming. Easing: `ease-standard-*` for elements visible throughout the motion (and panels that slide away but stay nearby), `ease-entrance-*` for elements arriving, `ease-exit-*` for elements leaving for good; pick the `-productive` or `-expressive` variant to match. Never autoplay or flash; honor `prefers-reduced-motion` and make every state change readable without motion.

**Backgrounds and imagery.** Flat color from the layer tokens; no gradients outside AI presence (below), no textures, no decorative illustration inside product UI. Photography and pictograms are used for marketing and onboarding surfaces only.

**AI presence.** Mark every piece of AI-generated or AI-recommended content, from one field to a whole page, with an `AILabel`, and give it an explainability callout (`AILabelContent`) that starts with a short summary and offers detail on demand. AI styling (the soft gradient and glow on tiles, the `cds--tile--decorator` treatment, `AISkeleton` loading) identifies AI and is never decoration: keep the glow at container edges so text contrast is unaffected. An AI component works exactly like its standard version; when a person edits AI content it drops the AI styling and offers revert (`AILabel revertActive`). Use `ChatButton` for prompts and quick actions in assistant surfaces.

## Iconography

Carbon uses its own single-ink icon set: outlined or filled glyphs on a 16px (default), 20px, 24px or 32px grid. Icons inherit `currentColor` (`icon-primary` by default). Status uses the filled glyphs (`error--filled`, `checkmark--filled`, `warning--filled`) next to a label. No emoji and no icon fonts. The Icons asset group holds a 78-glyph subset copied verbatim from the source (the `Icon` component bundles the same glyphs, plus a few small inline approximations); use the `Icon` component to color them. The full set lives in the `@carbon/icons` package.

## Accessibility

Carbon targets WCAG 2.1 AA (the IBM Accessibility Checklist, which also covers Section 508 and EN 301 549). Every component here ships the roles, labels and keyboard support listed under **Accessibility** in its README; the consumer still owns the parts below.

- Contrast: text 4.5:1 on its surface (3:1 at 24px+ or 19px bold), and 3:1 for icons, control borders and the `focus` ring, in every theme. The token pairs named in this book meet it, except the source's intentional low-contrast pairs (`text-placeholder`, `text-disabled`, `support-warning` as a fill), which must never carry essential information.
- Never use color alone: status pairs a color with an icon and a word (`IconIndicator`, `ShapeIndicator`, notifications), charts add labels or patterns, links in running text are underlined (`Link inline`).
- Keyboard: everything works with Tab, Shift+Tab, Enter, Space, Escape and the arrow keys; focus order follows reading order; overlays trap focus while modal and return it to the trigger on close. Test every surface keyboard-only.
- Names: every field has a visible label (`hideLabel` keeps it for screen readers only, for example in table rows), every icon-only control has an `aria-label`/`iconDescription`, every region that updates (results counts, toasts, inline loading) is announced through a live region.
- Media and motion: no autoplay, no flashing, captions and transcripts for audio, reduced-motion alternatives.
- Language: plain words and a linear layout lower cognitive load; one primary action per view.

## Data visualization

Charts use the categorical palette tokens `data-vis-01` to `data-vis-14` in that exact order (01 Purple 70, 02 Cyan 50, 03 Teal 70, 04 Magenta 70, 05 Red 50, 06 Red 90, 07 Green 60, 08 Blue 80, 09 Magenta 50, 10 Yellow 50, 11 Teal 50, 12 Cyan 90, 13 Orange 70, 14 Purple 50): the order is curated so neighbouring series contrast. A chart with one series uses one of the one-color group (`data-vis-01`, `-08`, `-02` or `-03`). Encode status only with the alert palette `data-vis-alert-danger`, `-serious`, `-warning`, `-normal`, and always with a label. These values are the light-theme palette published on carbondesignsystem.com; the site's dark-theme toggle values are not published as text, so on g90/g100 they are inherited and should be checked before use.

For ordered values use a monochromatic sequential scale of one IBM hue in 10 steps (Blue 10 to 100 is `#edf5ff` `#d0e2ff` `#a6c8ff` `#78a9ff` `#4589ff` `#0f62fe` `#0043ce` `#002d9c` `#001d6c` `#001141`; Purple, Cyan and Teal work the same way), with the strongest step for the largest value: darkest on light themes, lightest on dark themes. For values that diverge from a midpoint use Red 80→10 with Cyan 10→80 for hot/cold data, or Purple 80→10 with Teal 10→80 otherwise; diverging scales are the same in every theme. Use a gradient only for a single-category visualization, never to show progression. Every chart needs a title, labelled axes with units, and a legend or direct labels.

## Components

Ninety-two components plus `Icon`, hand-written from the Carbon v11.99.0 SCSS and React source. They render with the real `cds--` class names and read every color from the theme tokens, so they follow white, g10, g90 and g100. Load `tokens.css`, `components/bundle.css`, React 18, `components/bundle.js`, then use `window.Carbon.<Component>`. Each component folder has a README (what it is, what it omits versus Carbon, rules) and a live preview. Compound sub-parts (`AccordionItem`, `TableRow`, `HeaderMenuItem`, `DialogBody`, `PageHeaderContent`, ...) are exported on `window.Carbon` and documented in their parent's README.

- **Actions:** `Button`, `ButtonSet`, `IconButton`, `CopyButton`, `ComboButton`, `MenuButton`, `Menu`, `OverflowMenu`.
- **Forms:** `Form` (+ `FormGroup`, `FormLabel`, `FormItem`), `TextInput`, `TextArea`, `PasswordInput`, `NumberInput`, `Search`, `Select`, `Dropdown`, `ComboBox`, `MultiSelect`, `Checkbox`, `CheckboxGroup`, `RadioButtonGroup`, `Toggle`, `Slider`, `DatePicker`, `TimePicker`, `FileUploader`.
- **Fluid forms:** `FluidForm`, `FluidTextInput`, `FluidTextArea`, `FluidNumberInput`, `FluidSearch`, `FluidSelect`, `FluidTimePicker`, `FluidDropdown`, `FluidComboBox`, `FluidMultiSelect`, `FluidDatePicker`. Label inside a 64px field, no helper text, messages inside the field under a divider.
- **Data:** `DataTable`, `DataTableSkeleton`, `Pagination`, `PaginationNav`, `StructuredList`, `ContainedList`, `TreeView`, `Accordion`, `CodeSnippet`, `OrderedList`.
- **Navigation:** `UIShell` (header, `HeaderMenu`, `HeaderPanel` with `Switcher`, side nav), `HeaderPanel`, `PageHeader`, `Tabs`, `Breadcrumb`, `ContentSwitcher`, `Link`.
- **Containers:** `Tile` (+ `ClickableTile`), `ExpandableTile`, `SelectableTile`, `RadioTile` (+ `TileGroup`).
- **Overlays:** `Modal`, `Dialog`, `Popover`, `Tooltip`, `DefinitionTooltip`, `Toggletip`.
- **Feedback and status:** `InlineNotification`, `ActionableNotification`, `ToastNotification`, `Callout`, `Tag`, `DismissibleTag`, `OperationalTag`, `SelectableTag`, `BadgeIndicator`, `IconIndicator`, `ShapeIndicator`, `Loading`, `InlineLoading`, `ProgressBar`, `ProgressIndicator`, `SkeletonText`, `SkeletonPlaceholder`, `SkeletonIcon`.
- **AI:** `AILabel` (+ `AILabelContent`, `AILabelActions`), `AISkeleton` (`AISkeletonText`, `AISkeletonPlaceholder`, `AISkeletonIcon`), `ChatButton`.
- **Layout and type:** `Grid`, `Stack`, `Layer`, `AspectRatio`, `Theme` (+ `GlobalTheme`, `useTheme`), `Heading` (+ `Section`), `Text`.

- **Patterns (composed examples):** `PatternCreateForm`, `PatternResourceList`, `PatternSettings`, `PatternFiltering`, `PatternEmptyStates`, `PatternLoading`, `PatternNotifications`, `PatternConfirmation`, `PatternReadOnlyDisabled`, `PatternOverflowContent`, `PatternLogin`. They are showcase pages, not bundle exports; copy their structure. See the Patterns section.

Layering and theming: components use the `-01` layer tokens. Wrap them in `Layer` to step them to the `-02` and `-03` tokens on nested surfaces (`Layer level={1}` cannot reset an enclosing level); wrap a region in `Theme theme="g90"` to switch it to another theme, which also resets layering.

Known approximations. Carbon's `ai-*` tokens are not part of this token set, so the AI gradient, border and skeleton shimmer are built from `highlight`, `tag-background-blue`, `border-interactive` and `interactive`: close to Carbon in white, brighter and more saturated in g100. The warning glyph's exclamation mark is a cut-out because Carbon has no black token for it; some status and shape glyphs (caution triangles, undefined, unknown, informative, and every `ShapeIndicator` shape) are drawn inline. `UIShell` has no `$shell-header-*` tokens in v11.99, so the shell follows the theme (light in white and g10, dark in g90 and g100); `SideNavHeader` and `SideNavFooter` have no v11 SCSS and are styled on the v10 pattern. Clickable `Tag`s get the 1px operational border from the v11 SCSS. Motion durations and easings now live in `tokens.css` (the `duration` and `ease` families), so load `tokens.css` before `bundle.css`. Every component README lists what it leaves out (for example `DataTable` has no sticky header, inline edit or overflow column; `PageHeader` actions don't collapse into an overflow menu; `Callout` defaults to low contrast). Placeholder, disabled and warning-yellow pairs are Carbon's intentional low-contrast values.
